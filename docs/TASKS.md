Open items for the team:

- Container (done): the policy child runs as a separate unprivileged user inside the image; verified in CI by
  `tests/test_container.py` (no skips allowed), by the `--user 10001` and `--cap-drop ALL` fallback runs, and by
  strict mode (passes in the default image, exits 2 with `--cap-drop ALL`).
- `unallocated_payment` evidence still rests on a generator guarantee (no other receipt settles the invoice); a
  period-end open-items listing would make it provable from the cited records, at the cost of regenerating every
  episode.
- Evidence IDs: blank or over-long IDs make a submission invalid, as documented (DESIGN section 10). Integral float
  amounts are coerced by the environment and `grade` alike.
- Team section of README.md: names and roles (`TODO: names and roles.`).
- Not implemented: LLM-as-judge for explanations (idea 10); a time-zone twin pair for period errors (idea 1, second half).
- Docs: the four screenshots in `docs/media` were re-shot on the current viewer; the static design mocks in `docs/design`
  may predate version 0.2.0.
- Local `check` time (125 s in the committed report, Windows 10) is within the plan's target of under 5 minutes
  ([PLAN.md](PLAN.md), line 12).
- Code gaps from the review of commit `849d0da` that are still open. Each needs a code change or a team decision:
  - Currency has no length limit in the submit schema, so a valid submit can be padded over `MAX_LINE`: invalid in the
    child, scored in process. A length cap (`auditgym/schemas.py`) would make the parity claim true.
  - `resampled attempts stay rare` still counts every rejection, generator refusals and verification failures alike
    (`auditgym/check.py`). The separate line `no candidate episode was rejected by a correctness check` reports the
    verification side; splitting the counted check itself is open.
  - The organizer sweep runs only the count 2000 for invoices, which the invoice budget gate in `config.py` rejects with a
    ConfigError (validation accepts up to 2000 per key); the largest count it accepts is not swept (`tools/organizer_sweep.py`).
    The invoice gate rejects only totals of 1,651 or more; the slow band (about 900 sales invoices up to that total) fails
    after 16 attempts instead (`auditgym/config.py`, `min_read_pages`).
  - `duplicate_invoice` is injected only into purchase invoices (see DESIGN section 3). A sales-side variant would close the
    purchase-only search pattern.
  - The closed-run summary line counts kinds with the `closed_example/<policy>` label, so a closed run shows 80 kinds where
    the full check shows 79 (`auditgym/check.py`, `_EPISODE_PREFIX`).
  - The `Maximal` submit test in `tests/test_isolation.py` does not reach the size limit, because `currency` is unbounded.
  - The full CI log is not committed; `runs/ci/44694052476.txt` is an excerpt (DESIGN section 13).
